# WinForge — технические подробности

> Для пользователей — [README](../README.md). Здесь — как всё устроено внутри.

Конструктор своей сборки Windows и оптимизатор системы на Rust (egui).

Программа делает две вещи:

1. **Готовит свой образ Windows.** Создаёт `autounattend.xml` со вшитыми скриптами
   и `build.ps1`. Скрипт распаковывает официальный ISO, оставляет нужную редакцию
   и пишет флешку или загрузочный ISO. Твики, удаление приложений и установку программ
   выполняет сам установщик Windows в новой системе.
2. **Оптимизирует уже установленную Windows.** Применяет те же твики, удаление
   приложений и установку программ к текущей системе, с резервной копией и откатом.

## Безопасность

- **Сначала предпросмотр.** Любое применение начинается с чтения текущего состояния.
  Окно показывает, какие пункты уже применены, какие изменятся и какие на этой
  системе неприменимы. Изменения вносятся только после кнопки «Застосувати насправді».
- **Журнал отката.** Каждое применение записывает прежние значения реестра, типы
  запуска служб, состояние задач и компонентов в `%LOCALAPPDATA%\WinForge\backups`.
  Вкладка «Відкат змін» возвращает всё назад и удаляет ключи, которые WinForge создал.
  Удалённые встроенные приложения так не вернуть: их ставят заново из Microsoft Store.
- **Права администратора** нужны для изменений в HKLM, службах, DNS и hosts. Без них
  WinForge работает в режиме чтения и предлагает перезапуститься от администратора.
- **Защиту Windows не отключает.** Пункты про Defender, UAC, SmartScreen, VBS и BitLocker
  остаются в интерфейсе, но реальных действий у них нет: это сознательное решение.
- **Отсутствующие службы и задачи не создаются.** Если службы нет, пункт помечается
  как «не застосовно»: ни на живой системе, ни в образе не появляется мусорный ключ.

## Запуск

```powershell
cargo run
```

Готовый exe без консольного окна:

```powershell
cargo build --release
```

Он появится в `target\release\winforge.exe`. Положи рядом папку `catalog`,
если хочешь править каталоги без перекомпиляции.

## Своя сборка: флешка или ISO

1. «Образ Windows»: выбери официальный ISO. WinForge смонтирует его и прочитает
   список редакций прямо из заголовка `install.wim`/`install.esd`, без DISM.
2. Пройди шаги «Програми», «Приватність», «Оптимізація», «Видалення».
3. «Збірка» → «Куди записати»:
   - **Флешка** — для настоящей установки. В списке только съёмные USB-диски
     (системный и обычные диски туда не попадают), от 8 ГБ.
   - **ISO-файл** — для проверки в виртуалке.
4. «Робоча папка збірки» — где распаковывается образ, нужно ~30 ГБ. По умолчанию —
   диск с наибольшим свободным местом. Скрипт трогает только свою подпапку `WinForge-work`.
5. «Підготувати…» — файлы появятся в `%LOCALAPPDATA%\WinForge\build`:

| Файл | Что делает |
|------|-----------|
| `autounattend.xml` | Язык, раскладки, часовой пояс, локальная учётная запись, пропуск OOBE, обход TPM. Внутри — три скрипта ниже |
| `build.ps1` | Распаковка ISO → выбор редакции → файл ответов и драйверы → флешка или ISO |
| `specialize.ps1` | Удаление встроенных приложений, твики реестра и служб, компоненты Windows |
| `first-logon.cmd` | Задачи планировщика, твики классов пользователя и команды первого входа |
| `setup-apps.ps1` | Установка программ через winget и своих установщиков при первом входе |

Три скрипта лежат рядом только для чтения: установщик берёт копии, вшитые в
`autounattend.xml`, и распаковывает их в `C:\WinForge` новой системы.

6. «▶ Запустити збірку» запускает `build.ps1` от администратора **скрыто**, без окна
   PowerShell (10–20 минут). Прогресс — в самом WinForge: шаги, проценты копирования и
   записи ISO, предупреждения, итог, кнопки «Скасувати» и «📄 Журнал». Для флешки
   подтверждение `YES` вводится в WinForge до запуска. Скрипт пишет строки
   `STEP`/`PCT`/`WARN`/`DONE`/`ERROR` в `-ProgressFile`, а появление `-CancelFile`
   останавливает его. Запущенный вручную, без этих параметров, он работает как раньше.

**Почему твики применяет установщик, а не сборка.** Раньше скрипт монтировал
`install.wim` и правил реестр образа (`reg load`, `dism /Image`). На Windows 11 26H2
это ломается: кусты смонтированного образа не грузятся (`0x80070057`), и DISM не может
даже определить версию образа. Теперь образ не правится вовсе. В проходе `specialize`
установщик от имени SYSTEM распаковывает скрипты из `autounattend.xml` и запускает
`specialize.ps1` уже в устанавливаемой системе: HKLM пишется напрямую, HKCU — в профиль
по умолчанию (`C:\Users\Default\NTUSER.DAT`), из которого создаются все пользователи.
Журнал — `C:\WinForge\specialize.log`. Так сборка работает на любом ПК, а ISO делается
за 10 минут вместо 25. Драйверы кладутся в папку `$WinPEDriver$` носителя: установщик
сам ставит их и в среду установки, и в новую систему.

**Флешка.** Перед стиранием скрипт заново находит диск и проверяет, что это USB,
не системный и не загрузочный, с тем же серийным номером и размером, что выбраны
в WinForge. Затем показывает имя и размер и просит ввести `YES`. Флешка размечается
в FAT32 (её грузит UEFI любого ПК), `install.wim` делится на части `install.swm`
меньше 4 ГБ (их установщик Windows понимает сам), для старых BIOS-ПК пишется `bootsect`.

**ISO.** Если установлен Windows ADK, используется `oscdimg`. Если нет — встроенный
в Windows IMAPI2: UDF 1.02 и загрузчики BIOS + UEFI, как у Microsoft. Проверено:
такой ISO грузится в VirtualBox и в режиме UEFI с Secure Boot, и в BIOS, а `install.wim`
на 7 ГБ внутри него совпадает с оригиналом байт в байт.

**Дополнительно для образа** («Образ Windows»):
- **Wi-Fi** — имя сети и пароль. В `specialize` профиль добавляется через
  `netsh wlan add profile … user=all`, после чего файл профиля и его узел в
  `C:\Windows\Panther\unattend.xml` стираются. На самой флешке пароль остаётся
  открытым текстом в `autounattend.xml`, и WinForge об этом предупреждает.
  В профиль WinForge пароль не пишется.
- **Активація** — свой ключ продукта и/или KMS-сервер организации. Ключ едет отдельным
  вшитым файлом `C:\WinForge\product-key.txt`, ставится в `specialize` через
  `SoftwareLicensingService.InstallProductKey` и сразу стирается вместе со своими узлами
  в `Panther\unattend.xml` и `unattend-original.xml` (ещё раз — при первом входе: установщик
  переписывает эти файлы в конце). В журнал пишутся только последние 5 символов.
- **CompactOS** — `compact.exe /CompactOS:always` в `specialize`: система занимает на
  несколько ГБ меньше.
- **Доповнення для віртуальної машини** — если вторым приводом подключён диск VirtualBox
  Guest Additions (сертификаты Oracle добавляются через `VBoxCertUtil`) или VMware Tools,
  они ставятся тихо.
- Компоненты, которые нужно **включить** (.NET 3.5, WSL, Песочница, Hyper-V), ставятся с
  `/All` и берут файлы из `sources\sxs` носителя: .NET 3.5 не требует интернета.

Программы из каталога ставятся при первом входе через winget (нужен интернет). Итог
каждой программы — в `C:\WinForge\setup.log`.

**Свои установщики** («Мої програми»): по одному или **целой папкой** («📁 Додати папку
з інсталяторами»). WinForge находит все `.exe` и `.msi` (с подпапками до 2 уровней) и по
сигнатурам в начале файла определяет тип, чтобы подобрать ключи тихой установки:
MSI → `/qn`, Inno Setup → `/VERYSILENT`, NSIS → `/S`, WiX Burn → `/quiet`, InstallShield,
Advanced Installer, Squirrel. Если тип неизвестен, поле ключей подсвечивается, и их
нужно вписать самому (иначе установщик будет ждать кликов). Для образа файлы едут
на флешке/ISO в `WinForge\Installers`. Установка Windows копирует их в
`C:\WinForge\Installers` (если не вышло, `setup-apps.ps1` ищет носитель ещё раз),
ставит без интернета, `.msi` через `msiexec`, и удаляет после установки, если включено
«Видаляти інсталятори».

«Папка програм»: если оставить `C:\Program Files`, установщики выбирают папку сами.
Своя папка (например `D:\Apps`) даёт каждой программе подпапку `D:\Apps\<имя>`:
`winget --location` — это папка самой программы, общая папка свалила бы всё в один корень.
Установщики, которые не умеют ставиться в чужую папку (VC++, Telegram), ставятся по умолчанию.

## Тестовая виртуалка

`F:\WinForgeVM` (вне репозитория) — VirtualBox-виртуалка `WinForge-Test` с автоустановкой
Windows 11 и WinForge на рабочем столе, снимок «Clean Windows» для отката.
Скрипты и инструкция — `F:\WinForgeVM\tools` и `F:\WinForgeVM\ПРОЧТИ.txt`.
Свой ISO проверяется во второй виртуалке:

```powershell
powershell -ExecutionPolicy Bypass -File F:\WinForgeVM\tools\vbox-create.ps1 -Name WinForge-ISO -Iso D:\WinForge\WinForge_Windows.iso -NoConfig
```

## Каталоги

Меню строится из TOML-файлов в папке `catalog/`:

| Файл | Что внутри |
|------|-----------|
| `apps.toml` | Программы для установки через winget, по категориям и пресетам |
| `privacy.toml` | Твики приватности и телеметрии |
| `system.toml` | Оптимизации, интерфейс, обновления, безопасность |
| `bloat.toml` | Что удалить, по разделам `[[group]]`: приложения Microsoft, реклама партнёров, утилиты производителей ноутбуков, старые компоненты Windows |
| `cleaner.toml` | Что очищать (пути с `%ENV%` и `*`) |
| `registry.toml` | Разблокировка системных инструментов и исправления |
| `integrator.toml` | Пункты контекстного меню (правый клик) |

У каждого твика есть массив `actions`: что именно он делает.

```toml
actions = [
  { reg = 'HKLM\SOFTWARE\Policies\Microsoft\Windows\DataCollection', name = "AllowTelemetry", dword = 0 },
  { service = "DiagTrack", start = "disabled" },
  { task = '\Microsoft\Windows\Application Experience\Microsoft Compatibility Appraiser', enabled = false },
  { appx = "Microsoft.BingNews" },
  { appx = '*CandyCrush*' },                       # маски тоже можно
  { capability = "Microsoft.Windows.WordPad" },     # все версии и языки этой возможности
  { feature = "SMB1Protocol", enabled = false },
  { run = "powercfg -h off", undo = "powercfg -h on" },
  { reg = 'HKCU\...', name = "X", delete = true, when = "image" },   # только для образа
]
```

Значения реестра бывают `dword`, `qword`, `sz`, `expand`, `multi` и `binary`. Ещё можно
указать `delete = true`. Для команд `run` задаётся `shell = "cmd"` (по умолчанию) или
`"powershell"`. Пакеты Appx одного пункта удаляются одним запуском PowerShell.
`capability` удаляет возможность Windows (`Remove-WindowsCapability`) по имени до `~`;
откат возвращает именно удалённое через Windows Update. Поле `when` принимает `"live"` (только на этом ПК) или `"image"` (только
в образе). Тесты (`cargo test`) проверяют, что каждое действие распознаётся и у
реестровой записи ровно одно значение.

Интерфейс на украинском и английском (переключатель 🌐 внизу окна). Тексты
каталогов пишутся парами: `description = { uk = "...", en = "..." }`.

## Инструменты для установленной системы

Вверху меню — два режима. **«Зібрати нову Windows»**: Образ → Програми → Приватність →
Оптимізація → Видалення → Збірка. **«Налаштувати цю Windows»**: те же Програми,
Приватність, Оптимізація и Видалення, затем «Застосувати» (сначала предпросмотр, потом
точка восстановления и изменения с журналом отката) и все инструменты ниже.

| Вкладка | Что делает |
|---------|-----------|
| Очищення | Реальный подсчёт размера, удаление после подтверждения (заблокированные файлы пропускаются) |
| Реєстр | Снятие блокировок (Диспетчер задач, regedit…) и исправления |
| Автозапуск | Реальные записи из реестра и папок; выключение через `StartupApproved`, как в Диспетчере задач |
| Мережа | Текущий DNS, смена DNS на всех активных адаптерах (с шифрованием DNS-over-HTTPS: адреса регистрируются с `AutoUpgrade` и запасным обычным DNS), очистка кэша, пинг |
| Файл hosts | Реальный файл, наборы блокировок, сохранение с копией `hosts.bak` |
| Контекстне меню | Пункты правого клика и свои команды Win+R (App Paths) |
| Монітор дисків | Заполненность дисков, живой график ввода-вывода, самые активные процессы |
| Змінні PATH | PATH пользователя и системы: мёртвые пути, дубликаты, порядок |
| Активація | Состояние лицензии, установка своего ключа продукта, KMS-сервер своей организации (через WMI `SoftwareLicensingService`, без slmgr и без встроенных серверов). Ключ нигде не сохраняется |
| Обладнання | Процессор, память, видеокарта, плата, диски, сеть |
| Відкат змін | Журналы применений и их откат |

Перед настоящим применением (твики, реестр, контекстное меню) WinForge по умолчанию
создаёт **точку восстановления** Windows (`Checkpoint-Computer`). Windows делает не больше
одной в сутки: если сегодня точка уже была, новая не создаётся. Если «Захист системи»
выключен, шаг покажет ошибку, а остальное применится.

**Профиль** (кнопки внизу окна) сохраняет все отметки и настройки в `.toml`,
чтобы через год или на ПК друга всё вернулось как было. Пароль в профиль не пишется.

## Структура

```
src/
├── main.rs        запуск окна
├── app.rs         состояние, меню, задачи, генерация сборки, диалоги
├── run.rs         фоновое выполнение: предпросмотр и применение с прогрессом
├── profile.rs     сохранение и загрузка профиля
├── catalog.rs     загрузка каталогов, схема действий + тесты
├── tools.rs       состояние вкладок-инструментов, диски, DNS, hosts
├── sys/
│   ├── reg.rs     реестр (чтение, запись, восстановление)
│   ├── engine.rs  исполнитель действий, состояние, откат
│   ├── probe.rs   реальные данные: PATH, автозапуск, железо, диски, сеть, WIM
│   ├── clean.rs   очистка (пути с * и %ENV%)
│   ├── image.rs   autounattend.xml со вшитыми скриптами, specialize.ps1, build.ps1
│   └── mod.rs     права администратора, журналы отката
├── i18n.rs, theme.rs, widgets.rs
└── ui/            содержимое вкладок
```

```powershell
cargo test
cargo test -- --ignored   # + парсер PowerShell для скриптов и распаковка вшитых файлов
```

## Выпуск версии

Exe собирает GitHub Actions (`.github/workflows/release.yml`) на сервере с Windows:

```powershell
git tag v1.0
git push origin v1.0
```

Через ~10 минут на странице Releases появится релиз с файлом `WinForge.exe` — на него
ведёт кнопка DOWNLOAD в README (`releases/latest/download/WinForge.exe`). Имя файла
в релизе должно оставаться `WinForge.exe`. Пробная сборка без релиза: вкладка
Actions → Release → Run workflow, exe будет в Artifacts.

## Сборка exe: важное

- **Иконка** — `assets/winforge.ico` (наковальня, на которой «куются» окна Windows).
  `build.rs` вшивает её в exe через `assets/winforge.rc` (крейт `embed-resource`, нужен
  `rc.exe` из Windows SDK), поэтому она видна в Проводнике, ярлыках, на панели задач и в
  «Пуске». Окно и логотип в меню берут её из `assets/icon_128.rgba`. Перерисовать:
  `python assets/make_icon.py` (нужен Pillow).

- **Рантайм вшит** (`.cargo/config.toml`, `+crt-static`): exe не требует Visual C++
  Redistributable, которого нет на свежей Windows.
- **Окно рисуется через DirectX 12** (wgpu) с запасным OpenGL. Без драйвера видеокарты
  (свежая установка, виртуалка без 3D) DirectX 12 работает программно через WARP,
  а OpenGL там есть только версии 1.1. Если окно не создалось, WinForge показывает
  причину и пишет её в `%LOCALAPPDATA%\WinForge\error.log`.
- **`Cargo.lock` поправлен вручную**: у `gpu-allocator` стоит `windows 0.58.0`, как у `wgpu-hal`,
  иначе DirectX 12 не компилируется. После `cargo update` проверь:
  `cargo tree -i windows@0.58.0` должен показывать `gpu-allocator`.

## Что дальше

1. Полный прогон `build.ps1` от администратора: собрать ISO, поставить его во вторую
   виртуалку, проверить, что твики применились, а программы поставились.
2. Запись на настоящую флешку (код и проверки готовы, вживую ещё не запускалась).
3. Полностью автоматическая установка из своего образа: разметка диска и ключ — по желанию.
4. Проверка «уже установлено» для программ (winget list) и пакетов Appx в предпросмотре.
5. Точка восстановления Windows перед применением.
